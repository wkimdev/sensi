## 2. 제품 비전 및 목표

### 2.1 핵심 문제 (Problem Statement)

**현황:**
- HSP(민감한 기질을 가진 사람들)은 세상의 자극에 더 깊이 있게 반응하고 정처리하는 특성을 가짐
- 이들은 자신의 민감함이 약점이라고 느끼며 정서적 고립과 자기 부정감을 경험
- 기존 커뮤니티는 과도한 자극(광고, 자극적 콘텐츠)이 많아 HSP에게 피로감을 줌
- 자신과 비슷한 기질을 가진 사람들과 소통하고 공감받을 수 있는 안전한 공간이 부재

**문제:**
HSP 사용자들이 자신의 기질을 긍정적으로 받아들이고, 비슷한 사람들과 안전하게 소통할 수 있는 **공감 기반 커뮤니티**가 필요하다.

### 2.2 제품 비전 (One-liner)

> "민감한 영혼들이 모여 서로를 이해하고 위로받으며, 자신의 기질을 강점으로 재발견하는 따뜻한 공간"

### 2.3 MVP 목표

**정성적 목표:**
1. HSP 사용자들이 안심하고 자신의 경험을 나눌 수 있는 심리적 안전 기지 구축
2. 큐레이션된 콘텐츠(도서, 유튜브, 명언)를 통해 자기 이해와 정서적 지원 제공
3. 공감과 위로의 문화가 주도적인 커뮤니티 형성 (비난, 비교 문화 배제)

**정량적 목표:**
1. **사용자 확보**: 초기 3개월 내 1,000명의 활성 사용자 확보
2. **커뮤니티 활동**: 월간 게시글/댓글 500건 이상, 일일 활성 사용자 200명 이상
3. **재방문율**: 주간 재방문율 60% 이상 달성

### 2.4 성공 지표 (KPI/OKR)

| KPI | 목표 | 측정 방법 |
|-----|------|---------|
| **월간 활성 사용자(MAU)** | 1,000명 | GA4 활성 사용자 추적 |
| **평균 세션 길이** | 5분 이상 | GA4 세션 시간 |
| **주간 재방문율** | 60% 이상 | 쿠키 기반 재방문 추적 |
| **커뮤니티 참여도** | 월 500건 이상 게시글/댓글 | DB 게시글/댓글 수 |
| **콘텐츠 스크랩율** | 월 200건 이상 | DB 스크랩 기록 |
| **사용자 만족도** | NPS 40 이상 | 월 1회 설문 조사 |

## 3. 타겟 사용자 (User Persona)

### 3.1 페르소나 1: "사려깊은 지은"

**기본 정보:**
- 이름: 지은
- 나이: 28세
- 직업: 책임감 강한 마케팅 팀 매니저
- 학력: 4년제 대학 졸업

**특징:**
- 업무 성과는 뛰어나지만, 사소한 비판에도 마음이 상함
- 주말에는 과도한 자극을 피하고 혼자 있는 시간을 소중히 여김
- 예술, 철학, 개인 성장에 관심이 많음
- 타인의 감정을 깊이 있게 읽고 공감하는 능력이 뛰어남

**페인포인트:**
- 직장 동료들이 자신을 "예민하다"고 평가하며 자신감 저하
- 자신의 민감함이 장점인지 약점인지 헷갈림
- 비슷한 기질의 사람을 찾기 어려워 고립감을 느낌
- 자극적이고 빠른 SNS 문화에서 피로감 느낌

**니즈:**
- "나 같은 사람도 있을까?"라는 질문에 대한 답
- 자신의 민감함을 긍정적으로 재해석할 수 있는 콘텐츠
- 판단받지 않고 공감해주는 커뮤니티

**사용 시나리오:**
> 지은은 저녁 8시, 업무 스트레스로 피곤한 마음을 다스리기 위해 센시에 접속한다.
> 먼저 "예민한 사람의 강점" 도서 추천을 읽고, 비슷한 경험의 게시글을 찾아본다.
> 게시글에 댓글로 자신의 경험을 나누고, 공감 반응을 받으면서 위로받는다.
> 마지막으로 관련 유튜브 영상을 스크랩해 나중에 보기로 저장한다.

### 3.2 페르소나 2: "창의적인 준호"

**기본 정보:**
- 이름: 준호
- 나이: 32세
- 직업: 프리랜서 디자이너, 뮤지션
- 학력: 예술 대학 졸업

**특징:**
- 창의력과 미적 감각이 뛰어남
- 주변 환경의 색감, 음향, 에너지에 민감하게 반응
- 고독하지만 깊이 있는 관계를 중시함
- 자신의 HSP 특성을 이미 긍정적으로 수용함

**페인포인트:**
- 창의 작업 시 과도한 자극으로 인한 번아웃
- 일반 커뮤니티에서 자신의 감성을 이해하는 사람이 적음
- 정신 건강 관리 방법에 대한 정보 부족
- 혼자라고 느껴지는 순간이 있음

**니즈:**
- 비슷한 감성의 사람들과의 깊이 있는 연결
- 창의적 활동을 지속하기 위한 정신 건강 팁
- 영감을 주는 위인, 예술가 사례

**사용 시나리오:**
> 준호는 창의 작업으로 지쳐 있던 어느 날, 센시의 위인 명언 섹션을 본다.
> 비슷한 기질의 역사적 인물들의 명언을 읽으며 용기를 얻는다.
> 커뮤니티에서 "창의 활동 시 자극 관리법" 게시글을 발견하고 댓글로 자신의 팁을 공유한다.
> 함께 책을 읽는 사람들을 발견하고, 스크랩해 나중에 함께 이야기할 생각을 한다.

### 3.3 사용자 여정 맵 (Main User Journey)

**시나리오: "새로운 사용자의 온보딩 여정"**

```
[발견 단계]
    ↓
센시 서비스 인식 (SNS, 검색)
    ↓
    ↓
[가입 단계]
    ↓
SNS 로그인으로 간편 회원가입 (2-3단계)
    ↓
프로필 설정 (선택적: 관심사 태그 선택)
    ↓
    ↓
[탐색 단계]
    ↓
홈 피드에서 도서/유튜브/명언 큐레이션 둘러보기
커뮤니티 게시글 몇 개 읽기
다른 사용자의 활동 구경
    ↓
    ↓
[참여 단계]
    ↓
첫 번째 게시글 작성 (또는 댓글 남기기)
다른 사용자의 게시글에 공감 반응 누르기
좋은 콘텐츠 스크랩
    ↓
    ↓
[심화 단계]
    ↓
정기적인 커뮤니티 방문
관심 있는 게시글에 댓글로 대화 나누기
콘텐츠 공유 및 토론
마이페이지에서 스크랩 모음 정리
```

### 4.2 기능 우선순위 설명

- **P0 (필수)**: MVP 출시를 위해 반드시 필요한 기능

## 10. 용어 정리 (Glossary)

| 용어 | 정의 | 예시/설명 |
|------|------|---------|
| **HSP (Highly Sensitive Person)** | 타고난 신경계의 민감함으로 인해 주변 자극을 깊이 있게 처리하는 기질 특성 | Elaine Aron의 연구 기반, 인구의 약 15-20%가 해당 |
| **공감 반응** | 사용자가 게시글/댓글에 대해 나타내는 공감의 표시 (♥ 하트/공감 이모티콘) | "따뜻한 공감" 문화 강조, 좋아요 대신 사용 |
| **큐레이션** | 전문가가 선정하여 추천하는 콘텐츠 모음 | 도서, 유튜브 영상, 명언 등 정성적으로 선별된 리스트 |
| **스크랩** | 사용자가 나중에 다시 보기 위해 저장하는 콘텐츠 | 북마크와 유사, 마이페이지에서 관리 가능 |
| **페르소나** | 서비스 타겟 사용자의 대표적인 프로필 및 행동 패턴 | "사려깊은 지은", "창의적인 준호" 등 |
| **MVP (Minimum Viable Product)** | 핵심 기능만 포함하여 빠르게 출시하는 최소 제품 버전 | Phase 1: 6주 개발, 이후 기능 추가 |
| **OKR (Objectives and Key Results)** | 목표 달성을 위한 주요 결과 지표 | 예: 목표 "사용자 만족도 향상", KR "NPS 40 이상" |
| **KPI (Key Performance Indicator)** | 제품 성과를 측정하는 핵심 지표 | MAU, DAU, 재방문율 등 |
| **SEO (Search Engine Optimization)** | 검색 엔진 최적화를 통한 유기적 방문 증가 | Meta 태그, 구조화된 데이터, 페이지 속도 |
| **OAuth 2.0** | 제3자 서비스의 계정으로 로그인하는 개방형 표준 | Google, Apple, Naver, Kakao 로그인 |
| **JWT (JSON Web Token)** | 클라이언트와 서버 간 정보를 안전하게 전달하는 토큰 방식 | Access Token, Refresh Token 포함 |
| **API** | 애플리케이션이 요청하고 응답받는 데이터 통신 인터페이스 | REST API, GraphQL 등 |
| **CORS (Cross-Origin Resource Sharing)** | 다른 도메인의 리소스 접근을 제어하는 보안 정책 | 화이트리스트 기반 도메인 허용 |
| **UI/UX** | UI: 사용자 인터페이스 (버튼, 폼 등)<br/>UX: 사용자 경험 (사용 흐름, 만족도) | 디자인과 사용성의 통합 |
| **반응형 디자인** | 다양한 화면 크기에 자동으로 맞춰지는 웹 디자인 | 모바일, 태블릿, 데스크톱 모두 지원 |
| **라이트하우스** | Google의 웹 성능/접근성/SEO 측정 도구 | 성능(Performance), 접근성(Accessibility), SEO 점수 |

## 11. 부록: 의사결정 기록

### 11.1 설계 선택 사항

**Q. 왜 SNS 로그인(OAuth)만 제공하는가?**
- A: 초기 가입 장벽 최소화, 개인정보 관리 부담 감소, MVP 빠른 출시
- 향후: Phase 2에서 이메일/비밀번호 옵션 추가 검토

**Q. 왜 콘텐츠(도서/영상)를 사용자가 생성하지 못하게 하는가?**
- A: 초기 단계에서 큐레이션 품질 보장, 관리 부담 최소화
- 향후: Phase 3에서 사용자 추천/리뷰 기능 추가 검토

**Q. 왜 모바일 앱이 아닌 웹으로 먼저 시작하는가?**
- A: 개발 속도, 배포 용이성, 반응형 웹으로 모바일 지원 가능
